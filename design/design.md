# 项目设计灵感记录（头脑风暴阶段）

> 状态：设计中，未落地。本文件忠实记录想法，可随时修订。

## 一句话

一个 MCP 网关，让 AI（Claude/Codex/任意 MCP 客户端）能操作任何"能出网 + 能跑脚本"的远程环境。

## 三端架构

```
本地 Agent 端（Claude / Codex / 任意可连 MCP 的客户端）
    │  通过网关签发的秘钥鉴权
    ▼
MCP 网关（有公网 IP / 地址）
    ▲  通过网关签发的秘钥连接
远程脚本端（agent，用户在目标区域注入的模板脚本）
```

- **远程脚本端**：用户在目标区域注入模板脚本，**通过命令行参数**声明脚本的名字 + 简单描述运行区域（跑在哪、干嘛的）。
- **MCP 网关**：中央节点。管 agent 连接、管权限、管鉴权。
- **本地 Agent 端**：只要配置好，连上网关就能用。换客户端（Claude/Codex/Cursor 等）只需配置。

## 鉴权模型

系统里有两把钥匙，各管各的，正交不互相替代：

- **Claude 端令牌（本地端 ↔ 网关）**：管"可见性"——决定该本地端能看到/管理哪些远程脚本（scope 在签发时定死，不是运行时过滤）。类比门禁卡，证明你能进哪几栋楼。
- **脚本令牌（远程脚本 ↔ 网关）**：管"权限"——决定脚本连上网关后能执行哪些操作。类比工牌，证明你进去后能操作哪些机器。脚本连上网关默认零权限，需要带令牌才有权限。

### 脚本令牌的两种粒度（同一令牌的两档）

只有一种"脚本令牌"，签发时选两档权限之一：

- **继承签发人全权限（快捷档）**：签发一个代表"你"的令牌，任何用它启动的脚本自动继承你的全权限，不用逐脚本授权。适合一个人单机用，脚本启动参数带令牌就能跑，此后几乎不用再进网页。
- **自定义精确权限（细粒度档）**：逐脚本签发专属令牌，权限精确到"这脚本能删哪、能跑哪、能传哪"。适合多脚本多权限、给不同人用，依赖网页持续管理。

网页提供"令牌创建 + 权限配置"一套界面；快捷档创建后几乎不用再进网页，细粒度档则要经常进出网页管理。

## 授权模型（给脚本权限的两种方式）

1. **网关网页管理端**：手动给脚本分配权限。
2. **本地端秘钥**：因为秘钥已声明"能管理哪些脚本"，本地端可以经由此给它管辖的脚本授权。

## 权限粒度

操作级权限，按 **操作 × 路径** 两层一起配置：
- **操作**：删除文件、创建文件、执行命令、上传、下载、等。
- **路径**：默认所有路径；授权时操作 + 路径可以一起配（例如"只能删除 `/mnt/workspace/tmp` 下的文件"）。

## 权限生命周期（长命 vs 短命）

权限的生命周期应跟随脚本的生命周期，网关支持两种授权方式：

- **长生命周期脚本**（魔搭 / GPU 云 / 内网机器，活几天~几个月）：用网页端或秘钥**事后授权**，权限常驻。
- **短生命周期脚本**（CI/CD 容器，跑完连环境一起销毁）：等事后授权环境早死了。所以权限在**注入那一刻**由操作者通过**启动参数声明**（如 `--capabilities exec,upload --allowed-paths /tmp/artifacts`），绑定该实例 token，进程一死权限跟着消亡。脚本仍然不自我授权——授权动作发生在注入时，且**网关校验声明的能力必须是该 token/scope 允许的子集**，不能越权自我声明。

## 网关层拦截

脚本默认零权限只是"声明"，**真正拦截在网关**：本地端发的每个命令，网关先在权限表查一遍——命中白名单才下发到脚本，不在白名单直接拒绝（命令到不了脚本）。脚本是无状态哑巴，只信网关放行过的命令。

## 审计日志

日志放**网关**，不放脚本。脚本会被攻破/被黑（黑客能改脚本上的东西），但改不了网关上的日志。出事后靠网关日志追溯"当时跑了什么"。账本存总行，不存分行。

## 传输加密

明文 TCP 上发秘钥等于把钥匙挂门口。传输必须加密（TLS），秘钥鉴权才有意义。

## 多语言（未来）

暂时脚本用 Python，之后适配多种语言（Go / bash / 其他）。**前提是先定义语言无关的线协议（纯 JSON + 版本号）**——协议定了，各语言脚本就是"照着协议各写一份"，网关零改动。换语言是加菜，不是返工。

## 线协议（wire protocol，设计阶段先定死）

语言无关，纯 JSON + 版本号（`{"v":1, ...}`），所有字段先留位，后续实现：

- **心跳 / ping-pong**：agent 与网关之间长连接，定期互相 ping，超时判定断开，agent 自动重连。工程必需品，协议阶段定死，不用后补。
- **流式输出**：`stream: true/false` 参数。默认 false（命令跑完一次性返回）；true 则边跑边吐输出，像真实终端。解决长任务（如训练）跑半小时 AI 以为挂了的问题。设计阶段先占位，后续实现。
- **持久 shell 会话**：`session_id` 字段。默认每条命令独立执行（每次起新 subprocess，`cd /xxx` 不保留）；带 `session_id` 则在同一 shell 会话里连续跑命令，目录、环境变量保留。对训练工作流是刚需。

- GPU 云平台
- CI/CD 容器
- 内网机器 / IoT
- 任何"能出网 + 能跑脚本"的环境

## 已否决（讨论过，明确不做）

- ~~秘钥绑定"能对脚本做什么"~~：秘钥只管"能看到/管理哪些脚本"（身份 + 可见性），不绑定操作权限。理由：秘钥与权限是两条正交的轴——权限改了不用动秘钥；秘钥泄露也不直接等于能操作脚本。操作权限单独走权限机制管。
